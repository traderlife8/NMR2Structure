**目标**: 程序推导归属表 vs 真实归属表 (clxh100) 匹配行 ≥ 90%, 至少匹配 37/41 行
**基线 (2026-07-24 20:25)**: 19/63 = 30.2%, 19/41 = 46.3% (按行匹配率)
**真实归属表**: 41 行 (36 CH/CH2/CH3 + 5 Cq)

## 改进点 #1 — HMBC 矩阵交叉验证 F1 投影 (2026-07-24)

### 思路
HMBC F1 投影 (pdata/99) 对 13C 维求和,信噪比高,但也会将 t1 噪声 / 旋转边带 /
折叠伪峰求和进来。这些伪峰在 HMBC 矩阵 (pdata/1) 中通常没有真正的伴随交叉峰。
真实 13C 峰必定在 HMBC 矩阵中有 ≥1 个 F1×F2 矩阵交叉峰。
因此用 HMBC 矩阵 F1 ±0.5 ppm 邻域内有 ≥1 矩阵峰 + F2 在合理 1H 范围 (0~12 ppm) 作为
通过准则,过滤伪峰。

### 代码变更
- `nmr_elucidator/io_bruker_2d.py`: 新增
  - `cross_validate_hmbc_projection_peaks(hmbc_spec, proj_peaks, f1_tol, f2_min, f2_max) -> List[ProjectionPeak]`
  - `cross_validate_hmbc_projection_with_min(hmbc_spec, proj_peaks, ...) -> (validated, rejected)`
- `nmr_elucidator/__main__.py` [2.85] 节: 集成交叉验证,在原有 SNR≥3 / top-N 过滤之前先剔除无矩阵峰的投影峰。meta 增加 `HMBC_Projection_Xval_Validated/Rejected`。

### 运行结果 (2026-07-24 20:42)
```
  -> 产物 B 加强 [HMBC 矩阵交叉验证]: 剔除 2 个投影伪峰 (无 HMBC 矩阵交叉峰), 保留 51/53
  -> 产物 B [HMBC F1 投影]: 投影 51 峰, 主谱 38, 交集 7, 投影独有 44
  -> 产物 C [HSQC 行切片]: 2 个切片
  [Derive] 归属表: 63 行
  -> 匹配率: 30.2% (19/63)
```

### 效果评估
❌ **效果微弱**: 仅剔除 2 个 (53→51), 派生仍 63 行,匹配率仍 30.2%。
**根因诊断**: HMBC 矩阵含 3512 个峰(过多),矩阵峰密度太高,几乎每个投影峰 ±0.5 ppm 内
都能找到 ≥1 个矩阵峰 → 通过率 51/53=96%。需要更严格准则。
**后续**: 改用 matrix max_SNR > 阈值、matrix 峰 F2 必须精确匹配已知 1H、或矩阵峰积分比例法。
**决定**: 改进点 #1 暂不取效果,转入 #2。

## 改进点 #2 — 提升 HMBC 补强 SNR 阈值 3.0 → 20.0 (2026-07-24)

### 思路
改进点 #1 为什么效果微弱——HMBC 矩阵有 3512 个峰 (F1 0~230 ppm)，几乎包含所有
可能的位置，现有 F1+O 阈值过宽 (53 → 51)。需要从投影*本身*的显著性而不是
矩阵交叉验证入手。投影峰 SNR 分布： 4 个 >=5000 (TRUE), 13 个 NOISE >=5000。
提升 SNR 阈值是最直接的严格化途径：只过滤 SNR >= 20 的投影峰进入补强。
(但这会同时过滤部分 TRUE 峰。)

### 代码变更
- `nmr_elucidator/__main__.py` [2.85] 节: HMBC 补强的 SNR 阈值从 3.0 提升到 20.0

### 运行结果 (2026-07-24 20:50)
```
  -> 产物 B 加强 [HMBC 矩阵交叉验证]: 剔除 2 个投影伪峰，保留 51/53
  -> 产物 B [HMBC F1 投影]: 投影 51, 主谱 38, 交集 7, 投影独有 44
     (补强到 derive 流程: top 16 by intensity, snr≥20)
  归属表: 53 行  季碳=13
  -> 匹配率: 35.8% (19/53)
```

### 效果评估
🟡 **表面**: 30.2% → 35.8% (升 5.6 ppt)。但 19 个匹配行**未变**。
原因: 提高 SNR 只是减少了 Cq 噪声行数 (25 → 15)，分母下降但分子不变。
未弥补任何未匹配的真实行。**不是真正的进展**。
**后续**: 需跳出 SNR 补强思路, 转向“补全缺失 CH 型行” —— 从 HSQC 出发重检
                  CHPair 是否覆盖全部 36 个 CH 行上的 H。

## 改进点 #4 — 2D 流程补齐 Pyr 1H 主谱积分 (2026-07-24)

### 思路
exp 31 Pyr 主谱不含 Bruker 计算的 integrals.txt，之前仅以 exp 21 CDCl3 积分推断
HSQC CHPair multiplicity。exp 31 是与 2D 同溶剂的谱，优先级高于 CDCl3。
已从 intrng + 1r 自动补算 14 个区间，归一为最小值 (3.55-3.68 region, value=438)
后:7.48-7.70 ratio=2.34 (CH2) 。大的区间 (0.48-1.41 ratio=35, 1.41-2.22 ratio=48)
代表多个峰叠加，不能用于单峰 H 数推断。

**问题**: Pyr 区间覆盖太宽，不能逐峰映射 H 数。需依赖以下方法之一:
   A. 谱峰窄区(0.1-0.3 ppm)中间可仹出严重重叠 → 几乎不足用
   B. HSQC 交叉峰强度作为 H 数 proxy
   C. main 1H 谱中每个峰独立进行窄区积分 (需重新计算积分区间与峰 1:1)

### 代码变更
- `nmr_elucidator/__main__.py`: `interpret_2d_sequential()` 的 `proton_integrals` 参数
  从 `problem.proton_integrals` (CDCl3) 改为
  `pyr_integrals_for_2d` (Pyr, 含自动计算的 14 区间)。

### 运行结果 (2026-07-24 21:30)
```
  归属表: 50 行  季碳=10
  -> 匹配率: 38.0% (19/50)
```

### 效果评估
❌ **未提**: 35.8%→38.0% 看似提升，但 19/50 中 19 未变 (补强上限 +Pyr 积分值未归一化)。
**原因**: `_integral_to_mult` 将 `round(integral)` 作为 H 数, Pyr 未归一的实际值 (438~21046)
远远高于 1·2·3, 以 “>4 H” 识别为 “unknown”, 未用于覆盖 DEPT 推断。
**改进点 #5 方向**: 需在 `interpret_2d` 里按 “谱峰谱区间归一化” (归一为 [0, 4] 区间)
然后再 round, 才能让 Pyr 积分在重叠区仍然能贡献比较。

### 代码变更 #5
- `interpret_2d._normalize_integrals()`: 以 25% 分位数归一积分值为 0~4。
- `_find_integral` 优先使用归一化值。

### 运行结果 (2026-07-24 21:50)
```

  归属表: 50 行  季碳=10
  -> 匹配率: 38.0% (19/50)
  类型分布: C=10  CH=27  CH2=8  CH2/CH3=5  CH3=0
```

### 效果评估
❌ **未提**: 多次种换儿为 0·3·5 H lable，但实际多重峰重叠区 (1.4-2.2 ppm)
比率~35-48 仍超过 4 限阷, 导致多个预期为 CH3 的峰被识别为 “>4 H unknown”。
实际证明: 推导表 **CH3=0** 但真实表 **CH3=6** → 全部 6 个甲基未检出。
**主要瓶颈**: Pyr 积分区间覆盖多个谱峰, 不能作为单峰 CH3 推断依据。
**改进点 #6 方向**: 使用 化学位移+多重峰型 经验表补充 CH3 检测 (0.7-2.2 ppm

### 改进点 #7 — 同 13C 多 HSQC 交叉峰 → CH2 (2026-07-24 22:30)

diastereotopic 2 H)。原 assembly 逻辑仅取 group[0] mult 作为最终类别。
如总表从 「1 个 H × CH」 误转为 「2 个 H × CH」 是高价值提升。

### 代码变更
- `assembly.py`: `mult = group[0][1].multiplicity` 后检查
  `if len(group) >= 2: mult = 'CH2'`。

### 改进点 #9 — 同时发现多个同 C 的 H (CH2 互变体) (2026-07-24 23:00)

**什间表提升**: 调验以尝试 top-3 H, 每个候选 H 主谱 1H 匹配则加入并去重,
确保每 C 多个 H 都被发现。

### 代码变更

### 改进点 #11 — CH2 升级加 dH > 0.1 ppm 条件 (2026-07-25 01:10)

### 思路
原 #7+#10 会盲目将 2+ Hs 升级为 CH2, 但很多情况下两个 HSQC 交叉峰的 H 化学位移
几乎相同 (dH <= 0.1 ppm), 这是噪声/重复峰而非真正的 diastereotopic H。
修改为: 仅当两个 H 的化学位移差 > 0.1 ppm 时才升级为 CH2。

### 代码变更
- `assembly.py`: CH2 升级逻辑改为:
  1. 计算 group 中所有 H 的化学位移范围 `dh = max(h_shifts) - min(h_shifts)`
  2. 如果原 mult 是确定的 CH/CH3, 保持原 mult
  3. 如果 dh > 0.1 ppm, 升级为 CH2 (真正的 diastereotopic)
  4. 如果 dh <= 0.1 ppm, 保持原 mult (可能是噪声/重复)

### 运行结果 (2026-07-25 01:10)
```
  归属表: 66 行
  类型分布: C=9  CH=18  CH2=38  CH3=1
  -> 匹配率: 36.4% (24/66)
  碳类型不一致: 11/24
```

### 效果评估
🟡 **类型改善但匹配数未变**: CH2 从 50 降至 38, CH 从 8 升至 18。
减少了 12 个假 CH2 升级, 但匹配行数仍为 24。
**原因**: 匹配数取决于 13C+1H 联合匹配, 类型改善不影响匹配数 (只影响 OK/DIFF)。
**后续** (#12): 需从"补全缺失行"入手, 而非"修正类型"。
主要缺失: CH3 (18/21/27), 糖区 (2'/3'/6a'/6b'), CH2 对 (2α/2β, 24a/24b)。

### 改进点 #12 — CH3 检测扩展: DEPT 说 CH2 但 1H 在 CH3 区 (2026-07-25 01:20)

### 思路

但 DEPT 有时会误判 CH3 为 CH2 (CH3 的 J 调制与 CH2 相似)。
扩展: 当 DEPT 说 CH2 但 1H 在 0.5-1.4 ppm 且 13C < 25 ppm 时, 也识别为 CH3。

### 代码变更
- `interpret_2d.py`: 增加 `elif mult == 'CH2' and 0.5 <= h_ppm <= 1.4 and c_ppm < 25.0: mult = 'CH3'`
